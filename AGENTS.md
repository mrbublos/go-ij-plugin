# Working rules

Before exploring the codebase, read [domain guidance](docs/agents/domain.md).
Before implementing or reviewing code, read [architecture](docs/architecture.md).

Keep changes proportional: features and substantial fixes use specs and tickets;
small, well-defined fixes can proceed directly. Keep unrelated cleanup separate.
Update documentation when behavior or project conventions change.

Before reading or publishing issues, read the [issue workflow](docs/agents/issue-tracker.md).
Before assigning triage status, read the [five triage roles](docs/agents/triage-labels.md).

A change is complete when its acceptance criteria are met, relevant checks have
been run and reported, and affected documentation and ticket progress are current.
Use the [README](README.md#development-and-verification) for verification expectations.
