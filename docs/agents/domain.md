# Domain docs

This project uses a single-context layout:
- `GLOSSARY.md` at the project root.
- Architecture decision records under `docs/adr/`.

Before exploring the codebase, read the glossary and ADRs
relevant to the work. If absent, proceed silently; create these documents when terms or
decisions are resolved.

Use glossary terminology in specifications, issues, and tests.
If a needed concept is missing, reconsider the term or resolve
and document the gap before using the term in implementation.

Explicitly identify any proposal that contradicts an existing ADR,
including the reason to revisit that decision.
